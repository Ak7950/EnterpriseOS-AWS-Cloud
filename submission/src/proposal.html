EnterpriseOS on AWS
A Cost-Safe Serverless and Event-Driven Cloud Architecture for Workforce Management
Avik Khetarpal (1024031066) · Shashwat Tewari (1024031065) · Humza Ali Choudhri (1024031070)
B.Tech 3rd Year Computer Engineering, Thapar Institute of Engineering and Technology · Lab Faculty: Ms. Ishani Rana

Problem Statement

EnterpriseOS is our workforce-management web application (employees, departments, attendance, leave approvals, projects, tasks, notifications and an audit trail), built with Node.js, Express and PostgreSQL in the Software Engineering course. It works, but it runs on a hosting platform that hides the infrastructure, so it does not show how a real cloud system is designed, secured, monitored and costed.

How can an existing web application be moved to Amazon Web Services so that it demonstrates core cloud-computing concepts (serverless compute, managed messaging, secret management, identity and access management, monitoring and infrastructure as code) without changing its business logic and without any personal expenditure?

Constraints: zero personal cost (no paid plans; any AWS credit used must be estimated and capped), the restrictions of the AWS Academy Cloud Developing sandbox, and full preservation of every existing feature and test.

Objectives

  1. Run the existing EnterpriseOS application on AWS Lambda behind an Amazon API Gateway HTTPS endpoint without changing its business logic.
  2. Keep all secrets out of the code, templates and logs using AWS Systems Manager Parameter Store.
  3. Move slow side-effects to an event-driven pipeline (Amazon SQS → Lambda worker → Amazon SNS) with retries and a dead-letter queue.
  4. Apply least-privilege IAM, encryption and request throttling.
  5. Add monitoring: structured logs, a health-check endpoint and Amazon CloudWatch alarms.
  6. Define the complete environment as infrastructure as code (AWS SAM / CloudFormation) with one-command deployment and verified cleanup.
  7. Automate testing and validation with GitHub Actions, keeping deployments manual and cost-checked.
  8. Estimate and cap cloud cost so that personal expenditure stays at ₹0.

Proposed Solution

LayerAWS service and approach
ComputeAWS Lambda runs the unchanged Express app through a small, dependency-free loopback bridge
Front doorAPI Gateway HTTP API (throttled at 10 requests/s), with a Lambda Function URL fallback
MessagingAmazon SQS queue and dead-letter queue, worker Lambda, Amazon SNS topic
Secrets and securityParameter Store SecureStrings, scoped IAM roles, TLS-only encrypted queues
MonitoringCloudWatch Logs (JSON, 7-day retention) and alarms for errors, 5xx responses and dead-lettered events
AutomationAWS SAM template, deployment, pre-flight and cleanup scripts, GitHub Actions CI

Scope and Expected Outcomes

  • In scope: serverless hosting of the web app and API, asynchronous leave/task events, secret storage, monitoring, infrastructure as code, CI/CD and a cost model.
  • Out of scope: a paid managed database, CDN, custom domain and real e-mail delivery (documented as future work).
  • Expected outcomes: a deployable AWS stack created from one template, all existing tests still passing plus new cloud tests, a demonstration costing only cents of credit, and complete documentation.

Tools and technologies: Node.js 24, Express 4, PostgreSQL/pg-mem, AWS Lambda, API Gateway, SQS, SNS, Systems Manager, CloudWatch, SAM/CloudFormation, GitHub Actions, AWS CloudShell.
