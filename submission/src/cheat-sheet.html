Likely questions: short answers

  • Why Lambda? No idle cost, auto-scaling, no servers to patch.
  • How does Express run on Lambda? Lambda gets JSON events; our bridge starts Express on 127.0.0.1 and replays each event as a real HTTP request (≈1 ms overhead, no new dependency).
  • Cold start? First request in a new container: ≈0.75 s locally (load secrets, start app, seed demo data); warm ≈1 ms.
  • Why SQS and SNS? SQS = durable queue with retries/DLQ for one consumer; SNS = fan-out to many subscribers.
  • Duplicates? At-least-once delivery; every event has a UUID for idempotent consumers (DynamoDB table is future work).
  • HTTP API vs REST API? Cheaper, lower latency, we don't need REST-only features.
  • Where's the database? Demo mode keeps synthetic data in memory (a managed DB bills hourly). Same code takes a PostgreSQL URL from Parameter Store; RDS is future scope.
  • Least privilege? Template creates scoped roles (no wildcards, tested); the Academy sandbox only allows LabRole.
  • How did you control cost? Serverless only, no free-tier assumptions, per-resource estimate, throttling, 7-day logs, $2 cap, cleanup script, a test that fails if paid resources appear.
  • What went wrong? The first real deploy found 2 bugs (empty SAM parameter; SQS policy naming two queues). CloudFormation rolled back cleanly; we fixed, added a test and redeployed.

If the lab session ended: redeploy (≈10 min)

Full steps with troubleshooting: docs/demo-day-runbook.md. The prompt must show EnterpriseOS-AWS-Cloud $ before running the scripts.

  1. AWS Academy → Cloud Developing → Sandbox → Start Lab → green → AWS → region us-east-1 → CloudShell.
  2. export AWS_REGION=us-east-1 AWS_DEFAULT_REGION=us-east-1
  3. cd ~ && rm -rf EnterpriseOS-AWS-Cloud && git clone https://github.com/Ak7950/EnterpriseOS-AWS-Cloud.git && cd EnterpriseOS-AWS-Cloud && npm ci
  4. STAGE=dev bash scripts/aws/put-parameters.sh
  5. CONFIRM_COST_CHECKLIST=yes STAGE=dev FRONT_DOOR=HttpApi SKIP_TESTS=yes bash scripts/aws/deploy.sh → deploy → y
  6. Copy the Application URL; log in; approve a leave once so the worker log exists before the demo.

Demo accounts (synthetic, password Demo@12345): admin@demo.com, manager@demo.com, employee@demo.com.

After the evaluation: cleanup

  1. In CloudShell: STAGE=dev DELETE_PARAMETERS=yes DELETE_SAM_BUCKET=yes bash scripts/aws/cleanup.sh → type enterpriseos-dev → wait for "Cleanup verified".
  2. Then click End Lab.
Why both? The sandbox deletes everything when the session timer reaches 0:00, but credits are used until then. cleanup.sh stops usage immediately and verifies nothing is left. Your personal AWS account has nothing deployed: never click "Upgrade" there, and keep AutoPay off.
