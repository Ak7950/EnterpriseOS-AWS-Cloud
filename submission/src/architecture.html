Request flow

  1. Browser sends an HTTPS request to API Gateway (throttled).
  2. API Gateway forwards a JSON event to the API Lambda.
  3. Cold start: secrets loaded from Parameter Store; Express started on 127.0.0.1.
  4. The bridge replays the event as a real HTTP request (client IP verified by AWS).
  5. Express runs auth, role checks and tenant-scoped SQL; the response returns to the browser.

Event flow

  1. A manager approves leave or assigns a task.
  2. The API writes the database rows, then publishes LEAVE_DECIDED / TASK_ASSIGNED to SQS.
  3. The worker Lambda validates and logs each event and publishes a summary to SNS.
  4. Only failed messages retry; after 3 attempts they move to the dead-letter queue, which raises a CloudWatch alarm.

Defined as code

  • One AWS SAM template: infrastructure/template.yaml
  • IAM: least-privilege roles, or LabRole in AWS Academy
  • No NAT gateway, load balancer, EC2 or RDS (no hourly charges)
  • Logs kept 7 days; 4 CloudWatch alarms
